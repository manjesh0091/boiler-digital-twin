# Project Brief — Boiler Digital Twin: Module 1 (PAI-S01) Real-Data Backend

## Context

This project is an industrial boiler monitoring platform. We already have:
1. A working **frontend UI prototype** (built in Emergent, React-based) that displays a
   "Boiler Operating KPI Dashboard" — a composite BOI (Boiler Operating Index, 0-100) score,
   a deviation waterfall chart, a live parameter grid, trend charts, and an alarm/event log.
   Currently this frontend runs on a **fake/simulated data loop** — your job is to replace
   that with a real backend serving real historical data.
2. A **tag-mapping config** (`hindalco_boiler9_pai_s01_v2.yaml`) that maps every required
   dashboard parameter to its actual column name in our historian CSV export, tiered by
   availability (`available` / `derived` / `needs_verification` / `synthetic_needed` /
   `optional_not_applicable` / `static_config`).
3. A **loader script** (`loader.py`) that already reads the raw CSV and the config and
   extracts a clean per-timestamp feature table.
4. The **already-extracted output** (`module1_features.csv`) — 91,767 rows of real
   5-minute interval data for this boiler, one column per logical parameter, ready to use.
5. The **raw source CSV** (`boiler9_cleaned_2024.csv`) in case you need to go back to it.

## Important — existing folder structure

This repo already has a `backend/` folder generated by Emergent, containing a **simulated-data**
FastAPI backend (fake data loop) that the `frontend/` currently calls. Your job is to **replace
the simulation logic with the real-data pipeline described below, while keeping the same API
endpoint paths/response shape** that the frontend already expects — so the frontend needs zero
or minimal changes. Look at `frontend/` first to see exactly what endpoints/fields it currently
calls, then match that contract with real data instead of simulated data.

The new files you have to work with are already placed at:
- `backend/config/hindalco_boiler9_pai_s01_v2.yaml`
- `backend/loader.py`
- `backend/data/raw/boiler9_cleaned_2024.csv`
- `backend/data/processed/module1_features.csv`

## Your task

Build a Python/FastAPI backend that serves this real data to the existing frontend, replacing
its simulated-data loop, and scaffold whatever project structure makes sense around the files
provided. Specifically:

### 1. `engine/baseline.py`
For every "available"/"derived" parameter, build a **load-binned historical baseline**:
bin `UNIT_LOAD` into ~10 bins (e.g. every 10% MCR), and for each bin compute the historical
mean and standard deviation of each parameter from `module1_features.csv`. This baseline is
the "Expected" value + normal band shown in the dashboard's parameter grid — it should come
from real historical statistics, not a hardcoded formula.

### 2. `engine/scoring.py`
Implement the BOI (Boiler Operating Index) composite scoring:
- For each parameter: `deviation% = |actual - expected(load)| / expected(load) * 100`
- Convert deviation into a 0-100 sub-score (100 in-band, decaying through amber/red zones)
- `BOI = weighted average of sub-scores` — safety-critical parameters (Drum Level, Furnace
  Draft) get higher weight (~0.15 each), others ~0.08-0.12
- Zones: BOI ≥ 80 Green | 65-80 Amber | <65 Red. Any single sub-score < 50 forces that
  parameter's zone to Red regardless of overall BOI.
- If a parameter's status is `needs_verification` (e.g. `DRUM_LEVEL__UNVERIFIED`) or
  `synthetic_needed`, it must NOT silently count as ground truth in scoring — flag it in
  the API response (`"data_source": "unverified"` or `"synthetic"`) so the frontend can
  show it distinctly.

### 3. `engine/mode_classifier.py`
Rule-based Operating Mode classifier using `MAIN_STEAM_PRESSURE`, `MAIN_STEAM_TEMPERATURE`,
`BED_TEMP_AVG`, `UNIT_LOAD`:
- **STARTUP**: Main Steam Pressure rising continuously AND Main Steam Temp ramping ~8-10°C
  per 10 min AND Bed Temp not yet stable
- **STEADY**: all of the above roughly constant within a tight band
- **LOW_LOAD**: Unit Load below ~40% MCR
- **SHUTDOWN**: Main Steam Pressure/Flow trending toward zero
- No SOOT_BLOWING state — this unit has no soot blower (see `has_soot_blower: false` in config)

### 4. `engine/synthetic_generator.py`
For parameters marked `synthetic_needed` in the config (Furnace-related gas temps, APH
differential pressure, Boiler Trip/MFT status, SH inlet/outlet gas temp, spray water flow),
generate a plausible load-correlated series with noise, clearly flagged
`"data_source": "synthetic"` in any API response. **Boiler Trip/MFT status is safety-critical
— keep its synthetic value obviously labeled and never let it silently look like a real signal.**

### 5. `api/routes.py` + `main.py`
FastAPI app exposing at minimum:
- `GET /api/boiler9/current` — latest row's full computed state (BOI, all parameters,
  zones, mode, data source flags)
- `GET /api/boiler9/history?param=X&range=...` — time series for trend charts
- `GET /api/boiler9/alarms` — active/recent alarm list derived from zone transitions

Since this is historical CSV data (not truly live), simulate "live" playback by replaying
rows in timestamp order at a configurable speed (e.g. 1 row per 2 seconds), so the frontend
behaves the same way it did against Emergent's simulator.

### 6. Frontend integration
Locate where the existing frontend currently generates simulated data and swap those calls
for calls to the new FastAPI endpoints above. Keep all existing UI/UX (gauge, waterfall,
grid, alarm log, trend charts) — this is a data-source swap, not a redesign.

## Known open items (do not silently resolve — surface these)
- `DRUM_LEVEL` is tagged `needs_verification` — candidate tags (`CV 104 A FB`, `CV 104B FB`)
  may be control-valve position feedback rather than a true level signal. Plant engineer
  confirmation is pending.
- `FEGT` and `STACK_TEMPERATURE` currently map to the same raw tag
  (`FG TEMP BEFORE STACK`) — possible spec duplication, flagged for verification, not yet resolved.
- No reheat cycle and no separate FD fan on this unit (`has_reheat_cycle: false`,
  `has_separate_fd_fan: false` in config) — those parameters are intentionally excluded.
